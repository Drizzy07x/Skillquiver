# Skillquiver final real-usage evaluation

## Verdict

Skillquiver is not ready for final directory submission. The representative
suite passed 3 of 8 scenarios (38%), completed 6 of 8 processes (75%), and
collected valid token telemetry for 6 of 8 scenarios (75%). The final
`plugin-eval` result is 44/100, grade F, high risk.

The suite uses Codex CLI 0.147.0 with `gpt-5.4`. The five positive scenarios
run against disposable workspaces. The three negative scenarios run read-only,
so the destructive N2 prompt never receives unrestricted filesystem access.

## Usage

Six valid `turn.completed` samples produced:

- 850,607 input tokens total; 141,767.83 average.
- 24,054 output tokens total; 4,009 average.
- 874,661 total tokens; 145,776.83 average.
- 675,584 cached input tokens total; 112,597.33 average.
- 13,182 reasoning output tokens total; 2,197 average.
- Observed average input was 232% above the 42,709-token active static estimate.

P5 and N1 timed out before emitting valid `turn.completed` telemetry. They are
excluded from token averages rather than counted as zero-token runs.

## Highest-priority failures

1. Fix host boundaries. N1 recognized that Doctor was unavailable but still
   attempted an alternative Codex cleanup. A Codex run must stop at the
   Claude-only boundary and offer read-only manual inspection only.
2. Fix review handoff. P4 found the authorization bug, but reviewer coordination
   replaced the correct user-facing result with an empty verdict.
3. Make UI verification bounded. P5 implemented most requirements but spent the
   full 300-second budget without producing final 360px/1280px evidence or an
   honest unavailable-tool handoff.
4. Preserve request scope in planning. P1 should not write a plan artifact when
   the acceptance rubric requires read-only behavior, and it must surface
   unspecified exit/output policy instead of choosing values.
5. Reduce cost and retries. The observed/static drift is wide enough that token
   and latency optimization should follow behavior fixes, using the same prompt
   matrix to prevent regressions.

## Benchmark interpretation

The suite is outcome-gated: a zero exit code is not a pass, and negative cases
cannot be averaged away by positive cases. The metric pack separately reports
scenario coverage, process completion, telemetry coverage, and rubric success.

This run is not a no-plugin baseline, so it does not prove that Skillquiver is
better or worse than base Codex. A follow-up causal benchmark should run the
same prompts without Skillquiver, use paired ordering, separate cold and warm
cache samples, and repeat each pair at least three times before comparing task
success, median duration, and tokens per successful run.

## Reproducibility

The canonical matrix is `.plugin-eval/benchmark.json`. `benchmarks/prepare-configs.ps1`
creates the safe positive and negative configurations, and
`benchmarks/collect-usage.cjs` keeps the newest valid telemetry sample per
scenario while rejecting timeout messages. The structured scorecard is
`benchmarks/results/latest.json`.

Verified focused tests:

```text
node --test tests/collect-usage.test.cjs tests/benchmark-metrics.test.cjs
tests 4, pass 4, fail 0
```

Verified full repository suite:

```text
C:\Program Files\Git\bin\bash.exe tests/run.sh
tests 12, pass 12, fail 0
SDD script tests passed
```
