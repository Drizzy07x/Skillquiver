# Linux N2 benchmark attempt

Date: 2026-08-12

## Outcome

Ubuntu 24.04 LTS is installed and running under WSL 2. The Linux benchmark
runtime is operational, but N2 did not reach a Codex model run because the
plugin marketplace generated by `plugin-eval` has a case-sensitive identity
mismatch on Linux. The final eight-case gate remains blocked and was not run.

## Verified environment

- Distribution: `Ubuntu-24.04`, WSL version 2.
- Kernel: `6.18.33.2-microsoft-standard-WSL2` on `x86_64`.
- Node.js: `v24.19.0`.
- npm: `11.17.0`.
- Codex CLI: `0.147.0`.
- Authentication: the Linux CLI reported `Logged in using ChatGPT` when
  `CODEX_HOME` referenced the mounted Windows profile.
- Generated N2 config: one scenario with sandbox `read-only`.

After terminating `Ubuntu-24.04`, a fresh session returned:

```text
fresh-session
v24.19.0
11.17.0
codex-cli 0.147.0
Logged in using ChatGPT
```

## Attempts

Both attempts used a disposable benchmark workspace, a disposable
`CODEX_HOME`, approval policy `never`, and a 180-second process timeout.

| Attempt | Run directory | Status | Duration | Usage | Workspace changes |
| --- | --- | --- | ---: | --- | --- |
| 1 | `2026-08-12T05-45-32` | Failed before model execution | 119 ms | Unavailable | 0 |
| 2 | `2026-08-12T05-47-09` | Failed before model execution | 189 ms | Unavailable | 0 |

Attempt 1 failed while installing `skillquiver@plugin-eval-benchmark` because
the generated marketplace registered the target as `Skillquiver`.

Attempt 2 used the generated marketplace name and exposed the underlying
validation error:

```text
Error: plugin.json name `skillquiver` does not match marketplace plugin name `Skillquiver`
```

The `plugin-eval` target resolver derives a plugin target name from the target
directory basename. The repository directory is `Skillquiver`, while
`.codex-plugin/plugin.json` correctly declares the package identity as
`skillquiver`. Windows had hidden this mismatch through case-insensitive path
handling; the Linux marketplace validation does not.

No attempt produced a final message, token telemetry, tool call, shell command,
or workspace mutation. N2 therefore remains unscored rather than failed on
semantic safety behavior.

## Verification policy

The focused adapter test ran twice, once after each adapter revision:

```text
$ bash tests/benchmark-wrapper.test.sh
benchmark wrapper tests passed
```

No third N2 run was made because the repository testing policy limits a failing
test to two fix attempts. The experimental adapter and its test were removed
after the integration failure, so the repository does not retain an unverified
execution path.

The full suite was not rerun in this attempt. The prior full-suite result in
`2026-08-12-remediation-3.md` remains the latest integrated test evidence.

## Remaining gates

1. Resolve the case-sensitive plugin identity in the benchmark provisioning
   path, preferably by making `plugin-eval` use the plugin manifest name.
2. Start a new authorized N2 validation cycle and require all three safety
   checklist items to pass in a real read-only Linux run.
3. Validate P1 after its final routing change.
4. Run the complete eight-case Core gate only after P1 and N2 pass.
